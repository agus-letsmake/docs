Package: `@ovenbits/make-testlab-playwright`

Day-to-day reporting is the **Playwright reporter**. The package also ships a
setup-only `testlab` CLI (`login` / `init`) — see [CLI login + init](/cli-sdk/cli-login-init).

Peer dependency: `@playwright/test` >= 1.52.0. Depends on
[`@ovenbits/make-testlab-client`](/cli-sdk/client).

## Install

Packages publish to **GitHub Packages** (`@ovenbits` scope). TestLab / Google
login does **not** authenticate npm.

Checked-in `.npmrc`:

```ini
@ovenbits:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

```bash
gh auth login
gh auth refresh -h github.com -s read:packages
# If the org uses SAML SSO, authorize the token for that org
export NODE_AUTH_TOKEN="$(gh auth token)"
npm install @ovenbits/make-testlab-playwright @ovenbits/make-testlab-client
```

| Error                     | Meaning                              | What to do                                       |
| ------------------------- | ------------------------------------ | ------------------------------------------------ |
| `401` / `unauthenticated` | Missing or invalid token             | Export `NODE_AUTH_TOKEN`                         |
| `403` / `read_package`    | Token works; package ACL denies read | SSO-authorize; ask an org admin for package Read |

The package ships compiled CommonJS so Playwright’s `require.resolve` reporter
loading works.

## Register the reporter

```ts
import { defineConfig } from "@playwright/test";

export default defineConfig({
  use: {
    // End-of-test screenshots feed Observed evidence fallbacks and result-row uploads.
    // Prefer "on" when you want pass + fail screenshots; "only-on-failure" is also supported.
    screenshot: "on",
  },
  reporter: [
    ["list"],
    [
      "@ovenbits/make-testlab-playwright",
      {
        // Optional: constrain keys to your catalog pattern
        // automationKeyPattern: "(?:CA\\d+|AUTH\\d+|PPC\\d+)(?:-[A-Z]+)?",
        // Or fully custom:
        // resolveAutomationKey: (test) => ...,
      },
    ],
  ],
});
```

Gate registration on `TESTLAB_PUSH=1` in CI if local runs should stay offline.

### Reporter options

| Option                 | Purpose                                                                 |
| ---------------------- | ----------------------------------------------------------------------- |
| `automationKeyPattern` | Regex fragment used for tag (`^@?(…)\b`) and title (`\b(…)\b`) matching |
| `resolveAutomationKey` | Custom `(test) => string \| null`; replaces pattern-based extraction    |
| `client`               | Override Client bindings (tests / advanced)                             |

Default pattern constant: `DEFAULT_AUTOMATION_KEY_PATTERN` (exported). Keys are
**free-form** — the default matches letter+digit tokens and hyphenated keys
(for example `DEMO-01`, `CASE12`) in **tags first**, then **title**.

## How results are sent

The reporter does **not** invent an execution. CI (or a local wrapper) must:

1. Call Client [`startExecution`](/cli-sdk/client) → set `TESTLAB_EXECUTION_ID`
2. Run Playwright with the reporter registered and `TESTLAB_PUSH=1`
3. Optionally set `TESTLAB_DEFER_COMPLETE=1` and call
   [`completeExecution`](/cli-sdk/client) in a cleanup step

If `TESTLAB_EXECUTION_ID` is unset, the reporter **no-ops** (no pushes). Local
dev typically leaves `TESTLAB_PUSH` unset so runs stay offline.

On each **final** test attempt, the reporter:

1. Resolves the automation key
2. Reads optional [runner identity](#runner-identity) annotations
3. Calls Client `pushResults` with `automationKey`, `status`, `duration`,
   `errorMessage`, and runner fields
4. When evidence is enabled, ingests [observed steps](#test-steps-observed-evidence)
   and uploads [screenshots / videos](#screenshots-and-videos)

Statuses map from Playwright → TestLab as:

| Playwright               | Pushed status                                 |
| ------------------------ | --------------------------------------------- |
| `passed`                 | `pass`                                        |
| `failed` / `interrupted` | `fail`                                        |
| `timedOut`               | `fail` (observed as `timed_out` for evidence) |
| `skipped`                | `skipped`                                     |

### Retries

Intermediate failed retries are held. Only the **final** attempt is pushed. If
Playwright later **skips** after a failed retry, the reporter still reports the
pending failure as `fail` and sets a non-zero exit code for unrecovered failures.

Missing automation keys are logged to stderr and skipped (no HTTP push).

With `TESTLAB_PUSH_REQUIRED=1`, push HTTP failures also set `process.exitCode = 1`.

### End of run

After waiting for in-flight pushes, `onEnd`:

1. Reports any **unfinished** expected automation keys as `blocked`
   (`errorMessage`: test did not finish before Playwright ended)
2. Unless `TESTLAB_DEFER_COMPLETE=1`, calls `pushResults` with an empty
   `results` array and `autoComplete: true`
3. Fails the Playwright run if unrecovered retry-then-skip failures remain

Unfinished / extra suite rows stay `todo` until reported. Extra cases on the
suite that this job never runs **block autoComplete** — keep suite membership
aligned with the catalog you execute. See
[Portable Catalog](/concepts/portable-catalog).

### Evidence attach is a second push

Status is pushed first. Result-row files are uploaded via `uploadAttachment`,
then a **second** `pushResults` attaches them to the same `automationKey`.
Kinds:

| Kind                     | When                                     |
| ------------------------ | ---------------------------------------- |
| `failure-screenshot`     | Failed result screenshot                 |
| `test-screenshot`        | Pass (or non-fail) result screenshot     |
| `critical-success-video` | Success video allowed by evidence policy |

Observed step screenshots use `uploadStepScreenshot` and do not go through that
second result push.

## Test steps (Observed evidence)

Prefer human-readable Playwright `test.step` titles. The reporter builds Observed
evidence in this order:

1. Human `test.step` titles (including those created by `runObservedStep` / `runStep`)
2. Else flattened non-hook/fixture auto steps (`pw:api`, `expect`, …)
3. Else a synthetic `Test result` step when Playwright reports none

### `runObservedStep` / `runStep` / `bindObservedPage`

Both helpers wrap `test.step`, print TTY progress (`🔄` → `✅` / `❌`), and attach
a per-step screenshot named `testlab-step-screenshot` when a page is available.

```ts
import { expect, test } from "@playwright/test";
import {
  bindObservedPage,
  runObservedStep,
  runStep,
  TESTLAB_STEP_SCREENSHOT_NAME,
} from "@ovenbits/make-testlab-playwright";

test("DEMO-01 navigates", async ({ page }) => {
  // Title-only overload
  await runObservedStep(page, "Navigate to home", async () => {
    await page.goto("/");
  });

  // Suite-prefixed TTY: 🔄 [demo] Assert heading
  await runObservedStep(page, "demo", "Assert heading", async () => {
    await expect(page.getByRole("heading")).toBeVisible();
  });
});

test("DEMO-02 with bound page", async ({ page }) => {
  bindObservedPage(page);
  try {
    await runStep("demo", "Open settings", async () => {
      await page.goto("/settings");
    });
  } finally {
    bindObservedPage(null);
  }
});
```

### Fixture pattern

Bind the page once so every `runStep` / nested helper can attach step screenshots:

```ts
import { test as base } from "@playwright/test";
import { bindObservedPage } from "@ovenbits/make-testlab-playwright";

export const test = base.extend({
  page: async ({ page }, use) => {
    bindObservedPage(page);
    try {
      await use(page);
    } finally {
      bindObservedPage(null);
    }
  },
});
```

Exported helpers: `TESTLAB_STEP_SCREENSHOT_NAME`, `bindObservedPage`,
`getBoundObservedPage`, `formatObservedStepLine`, `runObservedStep`, `runStep`,
plus observed-step collectors used by the reporter
(`buildObservedStepsForResult`, `collectStepScreenshots`, …).

<Tip>
  If you need TTY progress **without** uploading screenshots (for example MFA /
  signup UI), keep a local helper that only logs — do **not** call the package
  `runStep` / `runObservedStep`, or deny those keys via `TESTLAB_EVIDENCE_DENY`.
</Tip>

## Screenshots and videos

### Per-step screenshots

Attached as Playwright attachments named `testlab-step-screenshot`. The reporter
uploads them onto matching Observed steps via Client `uploadStepScreenshot`.

### End-of-test screenshots

When Playwright attaches a normal `screenshot` (from `use.screenshot`) and no
per-step shots exist, the reporter falls back to that image on the failed (or
last) observed step **and** uploads it on the execution result row via
`uploadAttachment`.

Configure Playwright:

```ts
use: {
  screenshot: "on", // or "only-on-failure"
}
```

If evidence is enabled and no screenshot is available, the reporter warns once:

> Set Playwright `use.screenshot` to `"on"` (or `"only-on-failure"`) …

### Success videos

When evidence policy allows success videos for a key, the reporter uploads a
Playwright `video` attachment as `critical-success-video`. Enable recording in
the spec or project (`test.use({ video: "on" })`) for those keys.

Policy is owned by the Client — see [Evidence](/concepts/evidence) and
[Reporting env](/concepts/reporting-env)
(`TESTLAB_EVIDENCE_MODE`, `TESTLAB_CRITICAL_SUCCESS_VIDEO_KEYS`, allow/deny).

## Runner identity

Optional Playwright annotations (on the test or result):

| Annotation type            | Result field       |
| -------------------------- | ------------------ |
| `testlab:runnerEmail`      | `runnerEmail`      |
| `testlab:runnerPersonaKey` | `runnerPersonaKey` |

```ts
import {
  RUNNER_EMAIL_ANNOTATION,
  RUNNER_PERSONA_KEY_ANNOTATION,
} from "@ovenbits/make-testlab-playwright";

test.info().annotations.push({
  type: RUNNER_EMAIL_ANNOTATION,
  description: "user@example.com",
});
```

Annotate as soon as credentials exist (including before auth completes) so a
failed sign-in still reports which account was used. Intermediate retries keep
the last known identity until the final push.

Exported helpers: `normalizeRunnerIdentity`,
`resolveRunnerIdentityFromAnnotations`, annotation constants.

## Extending the reporter

`TestLabReporter` is a Playwright reporter class you can subclass. Override
`onTestEnd`, then call `super.onTestEnd(test, result)` after any product-specific
filtering (for example stripping screenshots on auth-failure messages).

Also exported: `createAutomationKeyResolver` for the same key pattern the
reporter uses.

Do **not** upload MFA / signup UI. Prefer `TESTLAB_EVIDENCE_DENY` plus a local
TTY-only helper that does **not** call package `runStep`.

## Environment

Requires Client reporting env (`TESTLAB_URL`, `TESTLAB_API_KEY`,
`TESTLAB_PROJECT_ID`, `TESTLAB_PUSH=1`) plus:

| Variable                                           | Purpose                                      |
| -------------------------------------------------- | -------------------------------------------- |
| `TESTLAB_EXECUTION_ID`                             | From `startExecution` (required for pushes)  |
| `TESTLAB_DEFER_COMPLETE`                           | `1` so CI cleanup owns complete/reconcile    |
| `TESTLAB_PUSH_REQUIRED`                            | `1` to fail the process on push failures     |
| `TESTLAB_EVIDENCE`                                 | Opt out with `0` (on by default when push=1) |
| `TESTLAB_EVIDENCE_MODE`                            | `failures` (default), `critical`, or `all`   |
| `TESTLAB_EVIDENCE_ALLOW` / `TESTLAB_EVIDENCE_DENY` | Regex key gates                              |
| `TESTLAB_CRITICAL_SUCCESS_VIDEO_KEYS`              | Comma-separated keys for success video       |
| `TESTLAB_EVIDENCE_RETENTION_DAYS`                  | Retention hint (default `10`)                |

Full table: [Reporting env](/concepts/reporting-env).
