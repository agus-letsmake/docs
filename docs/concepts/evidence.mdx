**Evidence** is the reviewable artifact trail for a case result: Observed step
walkthroughs, per-step screenshots, result-row attachments, and optional success
videos.

## Enable / disable

With `TESTLAB_PUSH=1`, the Client enables evidence by default. Opt out with
`TESTLAB_EVIDENCE=0`.

Key gates (`TESTLAB_EVIDENCE_ALLOW` / `TESTLAB_EVIDENCE_DENY`) are
**env/pattern-only** — the packages do not hardcode product prefixes. Use deny
patterns to skip sensitive flows (for example MFA / signup UIs).

## Modes (`TESTLAB_EVIDENCE_MODE`)

| Mode                 | Screenshots                                                                                           | Success videos                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `failures` (default) | Failure evidence when policy allows the key; result screenshots follow `shouldUploadResultScreenshot` | No                                                        |
| `critical`           | Same screenshot gates                                                                                 | Only keys listed in `TESTLAB_CRITICAL_SUCCESS_VIDEO_KEYS` |
| `all`                | Same screenshot gates                                                                                 | Success videos for keys that pass allow/deny              |

Retention hint: `TESTLAB_EVIDENCE_RETENTION_DAYS` (default `10`) is sent as
storage metadata with uploads.

## Observed steps (walkthrough)

The Playwright reporter ingests a case attempt with ordered steps:

1. Prefer human `test.step` titles (`runObservedStep` / package `runStep`)
2. Else flatten Playwright auto steps
3. Else synthesize a single `Test result` step

HTTP: `POST /api/evidence/v1/ingest` via Client `ingestCaseAttempt`.

## Screenshots

| Source               | Attachment / API                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------- |
| Per-step             | Playwright attachment name `testlab-step-screenshot` → `uploadStepScreenshot`             |
| End-of-test fallback | Playwright `screenshot` attachment → Observed step + `uploadAttachment` on the result row |

Playwright must be configured with `use.screenshot: "on"` or
`"only-on-failure"` for end-of-test fallbacks. Prefer `runObservedStep` so each
human step gets its own shot.

Failure screenshot uploads also respect `shouldUploadFailureEvidence` (mode +
allow/deny). Pass screenshots respect `shouldUploadResultScreenshot`.

## Videos

Success videos upload when:

1. Evidence is enabled and the key passes allow/deny
2. Mode is `critical` (key in `TESTLAB_CRITICAL_SUCCESS_VIDEO_KEYS`) or `all`
3. Playwright attached a `video` (enable recording for that test/project)

Kind stored on the result: `critical-success-video`.

## HTTP surfaces

| Endpoint                                        | Helper                 |
| ----------------------------------------------- | ---------------------- |
| `POST /api/attachments/upload`                  | `uploadAttachment`     |
| `POST /api/evidence/v1/ingest`                  | `ingestCaseAttempt`    |
| `POST /api/evidence/v1/steps/:stepId/artifacts` | `uploadStepScreenshot` |
