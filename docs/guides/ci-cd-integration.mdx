## Overview

Prefer **`@ovenbits/make-testlab-playwright`** (and the shared Client package) for
CI reporting. Configure secrets once, start an execution per job, push on every
final test attempt, upload Observed evidence, then complete/reconcile in cleanup.

Shorter recipe: [GitHub Actions reporting](/docs/ci-automations/github-actions).
Copy-paste test + workflow: [Code examples](/docs/guides/examples).

## Prerequisites

- Project-scoped API key (`TESTLAB_API_KEY`)
- `TESTLAB_URL` and `TESTLAB_PROJECT_ID`
- Suite whose cases carry matching **automation keys**
- Playwright tests that expose those keys (tags or titles)
- Catalog import via Cases UI (Bootstrap is retired)

## Playwright (recommended)

### 1. Install

```bash
npm install @ovenbits/make-testlab-playwright @ovenbits/make-testlab-client
```

Authenticate `@ovenbits` against GitHub Packages (`read:packages`).

### 2. Register the reporter

```ts
import { defineConfig } from "@playwright/test";

export default defineConfig({
  use: { screenshot: "on" },
  reporter: [
    ["list"],
    [
      "@ovenbits/make-testlab-playwright",
      {
        // Optional catalog-specific pattern
        // automationKeyPattern: "(?:CA\\d+|AUTH\\d+|PPC\\d+)(?:-[A-Z]+)?",
      },
    ],
  ],
});
```

Documented fully under [Playwright SDK](/docs/cli-sdk/playwright):

- Sending results (`pushResults` on final attempts, retries, unrecovered skips)
- Observed steps (`runObservedStep` / `bindObservedPage`)
- Screenshots and success videos
- Runner identity annotations

### 3. CI lifecycle

| Step   | Responsibility                                                  |
| ------ | --------------------------------------------------------------- |
| Start  | Client `startExecution` → `TESTLAB_EXECUTION_ID`                |
| Run    | Reporter pushes results + evidence (`TESTLAB_DEFER_COMPLETE=1`) |
| Finish | Client `completeExecution(..., { forceReconcile: true })`       |

Copy-paste YAML: [GitHub Actions reporting](/docs/ci-automations/github-actions).

### 4. Evidence policy in CI

Typical defaults for product suites that include auth:

```yaml
TESTLAB_EVIDENCE: "1"
TESTLAB_EVIDENCE_MODE: "failures"
TESTLAB_EVIDENCE_DENY: "^(AUTH|SIGNUP)"
TESTLAB_CRITICAL_SUCCESS_VIDEO_KEYS: "SMOKE-01" # used when mode=critical
TESTLAB_EVIDENCE_RETENTION_DAYS: "10"
```

- Keep global Playwright `video` / `screenshot` off in CI if auth UI must not
  land in Actions artifacts; opt individual non-auth specs into screenshots.
- For `critical` success video, enable Playwright video only on those specs
  (`test.use({ video: "on" })`).

See [Evidence](/docs/concepts/evidence) and [Reporting env](/docs/concepts/reporting-env).

### 5. Runner identity

Annotate account-backed tests with `testlab:runnerEmail` (and optional
`testlab:runnerPersonaKey`) as soon as credentials exist so failed auth still
attributes the result. Non-account smoke can omit identity.

## Non-Playwright runners

Use [`@ovenbits/make-testlab-client`](/docs/cli-sdk/client) directly:

1. `startExecution`
2. `pushResults` per case (`automationKey`, `status`, optional runner fields)
3. Optional `uploadAttachment` / `ingestCaseAttempt` / `uploadStepScreenshot`
4. `completeExecution` with `forceReconcile` from cleanup

## Legacy Jest JSON script

Older Jest converter scripts may still exist in historical repos. Prefer the
Client package for new work. If you must map Jest JSON yourself, post to
`POST /api/automated-results` with `X-API-Key` and `X-Project-Id` — see
[API reference](/docs/api-reference/automated-results/push).
